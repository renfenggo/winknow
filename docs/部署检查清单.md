# Winknow 部署检查清单（安装前 / 安装后 / 复检）

> V7.0 第 12 周交付 | 使用对象：机房管理员 | 配套：设备安全页（AdminUI → 设备安全 → 开始检测）
> 记录要求：每台设备三段各执行一次，结果登记于 Winknow 人工核验（自动带入核验记录）

---

## A. 安装前（系统与固件准备）

| # | 检查项 | 方法 | 达标要求 |
|---|--------|------|----------|
| A1 | 系统版本 | `winver` | Win10 21H2+ / Win11（net8.0-windows 运行时可达） |
| A2 | 分区表 | Winknow 检测报告"系统盘（GPT/MBR）" | GPT（UEFI 部署）；MBR 需先评估是否迁移 |
| A3 | 固件模式 | 报告"模式：UEFI/Legacy" | UEFI（Legacy 机器先完成 UEFI 切换再部署） |
| A4 | 本机管理员账户 | 安装介质准备 | Winknow 安装/服务需要本地管理员 |
| A5 | 现有管控软件 | 控制面板查证 | 卸载旧 V6/其他管控（防双管控冲突） |
| A6 | BIOS 七项加固 | 按品牌矩阵设置（报告第六节有本机路径指引） | 全部达标（见兼容矩阵表一） |
| A7 | 外部启动验证 | 《USB 设备矩阵与启动验证方案》第 3 节 | USB PE/移动硬盘/PXE 启动尝试全部失败 |

## B. 安装后（软件部署确认）

| # | 检查项 | 方法 | 达标要求 |
|---|--------|------|----------|
| B1 | 服务状态 | `services.msc` | WinknowControl / WinknowGuard 均在运行 |
| B2 | 守护生效 | 停止 Control 服务，≤30s 内被自动拉起 | 守护拉起成功（退避 1s 起） |
| B3 | 单实例 | 双击启动第二份 ControlService.exe | 第二实例自动退出 |
| B4 | USB 存储禁用 | 插入 U 盘/移动硬盘 | 不出现盘符、不可作普通存储 |
| B5 | 键鼠正常 | USB 键盘鼠标输入 | 输入完全正常（HID 不受管控影响） |
| B6 | 摄像头/音频 | 视频课设备测试 | 正常（非存储外设放行） |
| B7 | 学生 IDE | VS/VSCode/Dev-C++ 启动与编译 | 正常（编程兼容策略生效，第 4 周） |
| B8 | 策略下发 | AdminUI 策略页 → 学生会话验证 | 黑名单进程被拦截、白名单放行 |
| B9 | 日志写入 | 制造一次进程拦截 → 维护日志页/CSV | 审计记录完整（含哈希链状态正常） |
| B10 | 设备安全评估 | 设备安全页 → 开始检测 | 评分生成；人工五项完成现场核验并记录 |
| B11 | 核验记录 | 导出报告第五节 | "核验有效"（VerificationCurrent = true） |

## C. 复检（周期性与事件触发）

| 触发条件 | 必查项 |
|----------|--------|
| 每学期开学 | 全表 B1-B11 + BIOS 七项抽检（重点 Secure Boot/USB Boot） |
| BIOS/固件更新后 | **强制全查**：BIOS 七项逐项复检（戴尔等品牌更新会复位设置）+ Winknow 重新评估（旧核验记录已自动失效，需重新人工核验） |
| 硬盘更换/系统重装 | A 段 + B 段全查 |
| 主板维修更换 | A 段全查（固件指纹变化 → 核验记录失效 → 重新核验） |
| 发现学生绕过尝试 | 该机 A6/B4/C 段启动验证 + 审计日志排查 |

## D. 无法自动化项登记（本机差异）

在 Winknow 设备安全页人工核验时填写备注，至少记录：

- 机型与 BIOS 版本（报告自动带出固件指纹）
- 与兼容矩阵不符的菜单路径（generic 机器必填）
- BIOS 密码托管位置（密封信封/保险柜编号——**不写明文密码**）
