## 二、本次对话定稿的需求：防破解 + 双模式

用户在交付第 13 周后提出防破解需求，经多轮讨论**方案已定稿但一行代码未写**（用户明确要求先出方案不动文件）。

### 用户的最终意图（原话归纳）

1. **有网模式**：实现远程监控 / 教师机监控
2. **断网模式**：锁机；解锁靠两路密码——
   - **动态密码**：服务端生成 TOTP，**电话口头告知**机器前的人
   - **固定密码**：预先告知客户的长密码（兜底）
3. **断外网就停摆（fail-closed）**——用户明确推翻了"离线宽限 7 天"的默认设计："现在这个时代，没网等同于不能用电脑"，断网锁机不损失正当用途，反而堵死"拔网线玩单机游戏"

### 已确认的设计参数（写入 policy 可调）

| 参数 | 取值 | 理由 |
|------|------|------|
| 心跳锚点 | **教师机（局域网）** | 只罚"学生拔自己网线"；学校外网断了课照上、管控照跑 |
| 断网宽限 | **5 分钟**（0~30 可配） | 扛网络抖动和学生机重启 |
| 开机等网窗口 | **2 分钟** | 显示"正在连接管控"，超时才锁 |
| TOTP 有效期 | **5 分钟一档** | 打电话念码的时间走得完（标准 60s 太短） |
| 应急解锁 | 本地维护密码（已有组件） | 网络全炸时教师走到机器前解锁，事件留痕 |

## 三、四阶段执行计划（等待用户说"开始"）

```
A  混淆接入打包流水线          （防"看懂"，先行）
B  双模式实现：心跳锚点+断网锁屏+双路解锁+AdminUI课堂总览   （防"拷走用"+远程监控）
C  重出正式包 → Stage 0 重做 → 回灰度三阶段 → 发 V7.0
D  云后端（V7.1，不阻塞发版）
```

### 阶段 A：混淆
- 选型 **Obfuscar**（只做符号重命名；不用 ConfuserEx/加壳——杀软误杀风险）
- 顺序铁律：**publish → 混淆 → 签名 → manifest**（混淆必须在签名前）
- 范围：services/Security/Core/Ipc 等库混淆；**AdminUI(WPF) 不混淆**（XAML 按名绑定）；IPC 消息类型/JSON DTO/`Result` 等反射契约类排除
- 顺带：PolicyFile 支持编码存储（学生记事本打开 policy.json 看不到禁用进程明文）
- 改动：新增 `installer/obfuscar.xml`，修改 `Build-Release.ps1`
- 验收：486 测试全过（测试跑未混淆构建）+ 混淆产物冒烟清单 + Verify-Release 全绿

### 阶段 B：双模式（新建 `src/Winknow.Licensing` 项目）
| 组件 | 职责 |
|------|------|
| `ILicenseProvider` | 验证端点抽象：`LanProvider`(教师机) / `CloudProvider`(V7.1)——为云后端预留，加后端不重写 |
| `DeviceLicenseClient` | 每 30 秒报 DeviceId，收签名令牌 |
| `LicenseToken` | DeviceId+签发时间+有效期+签名（防伪造） |
| `OfflineGraceStore` | DPAPI 缓存最近令牌（分钟级宽限） |
| `LicenseEnforcement` | 三态：在线/宽限中/锁定 |
| `TeacherLicenseServer` | 教师机侧轻量端点：名单查询+令牌签发 |
- **锁屏遮罩**：`SessionAgent` 加 `LockOverlay`（SessionAgent 本就跑在学生桌面会话，天然画遮罩；标准用户杀不掉 SYSTEM 服务下发的窗口）；锁/解锁命令走现有 `Winknow.Ipc`
- **双路解锁**：
  - 动态码 = 复用 `TotpGenerator.cs`（教师机 AdminUI 显示当前码 → 电话告知 → 学生机离线验证。TOTP 离线可验原理：共享密钥+时间两边各算；标准用户改不了系统时钟）
  - 固定码 = 复用 `MaintenancePassword`/`MaintenanceSession`/`RecoveryCodeStore`
- **课堂总览**：AdminUI 新增 `ClassroomPage`（在线/离线/锁定状态、拦截事件实时流、断网告警、远程锁/解锁/下发策略）
- 未授权机器（名单外拷贝安装）→ 进 `SafeDegradedMode` 不退进程
- 授权/解锁事件写入第 9 周日志哈希链留痕
- 已知弱点（用户知情接受）：TOTP 共享密钥存学生机（ACL+混淆保护，可轮换）；教师机/交换机故障=全班锁（运维手册写明）

### 阶段 C：出包回灰度
- 重跑流水线（含混淆）→ Stage 0 装机核验**重做**，报告新增"第八节 授权验证"+演练：拔线锁定/电话报码解锁/固定码解锁/插线自动解锁
- `Collect-CanaryMetrics.ps1` 加采 2 项：授权心跳成功率、断网锁定触发次数（正常≈0）
- `发布决策检查单.md` 加 3 项签核

### 阶段 D：云后端（V7.1）
- ASP.NET Core 最小 API + SQLite：心跳/事件接收、策略下发、TOTP 码查询（管理员鉴权）、告警推送
- **管理端=手机能开的简单网页**（最大价值：管理员不在教师机旁也能看状态、报码）
- **后端只做通道不做信任**：策略/令牌仍走现有签名体系，后端被打穿也签不了名、伪造策略被学生机签名校验拒收——这是"后端可以晚做、做错不致命"的底气
- 学生机零重装：配置切双锚点（教师机/云任一可达=在线）
- 部署二选一：校内服务器（数据不出校）vs 云主机（多校区）

## 五、环境备忘（踩过的坑，别再踩）

- **PowerShell 5.1 中文 .ps1 必须 UTF-8 带 BOM**，否则中文串解析报错
- 宿主包装（Trae safe_rm_aliases）下 `$PSScriptRoot` 在 param 默认值求值阶段为空 → 脚本体内解析 `$scriptRoot` 并强制绝对化输出路径
- 测试证书（自签名）`signtool verify /pa` 必失败（无信任链）→ 用 `Get-AuthenticodeSignature` 比对指纹代替
- 签名流水线顺序缺陷已修：manifest 必须在**签名之后**生成/刷新（签名改变文件字节）
- 测试命令：`dotnet test -c Release`（预期 486 项）；产物核验 `canary\Verify-Release.ps1`；装机核验 `-Installed` 模式
