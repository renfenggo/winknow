# 编程课堂电脑管控系统 V7.0 基础版开发计划书

> **版本**：V7.0 软件与设备安全增强版  
> **基线**：V6.0 架构与可维护性增强版  
> **计划周期**：13 周  
> **目标**：完整保留 V6.0 的威胁模型、安全边界、Service + SessionAgent 架构、安全 IPC、更新回滚、可信恢复、日志完整性、密钥管理、隐私治理、失败策略和验收体系；删除 AppLocker 与 BitLocker 依赖，增强 WMI 软件管控，并新增 BIOS/UEFI 部署安全、外部启动防护、Secure Boot 检测和设备安全评分。

---

## 一、开发目标

V7.0 必须完成以下升级：

1. 建立正式威胁模型。
2. 拆分 ControlService 与 SessionAgent。
3. 建立安全 IPC。
4. 使用 WMI 实时监听、启动扫描和 1～2 秒周期扫描构建软件管控引擎，并明确其属于启动后快速关闭机制。
5. 修正服务、进程和安全模式保护设计。
6. 增加离线维护、授权卸载和恢复工具。
7. 增加签名更新、A/B 部署和自动回滚。
8. 增加网络代理、PAC、DNS、浏览器策略防绕过。
9. 增加重启风暴保护和安全降级。
10. 完善日志完整性、密钥管理和隐私治理。
11. 新增 BIOS/UEFI 管理员密码、USB/外部/PXE 启动限制、Boot Order、Boot Menu 和 Secure Boot 的设备部署验收。
12. 完成兼容性、安全、故障注入、多品牌设备核验和真实教室灰度测试。

---

## 二、开发原则

1. 先架构，后加固。
2. 先记录和验证白名单，再启用强制关闭；对设备固件项坚持“可检测则检测，不可检测则人工核验”。
3. 所有安全功能必须有恢复通道。
4. 所有更新必须可回滚。
5. 不以进程名、命令关键字或代码混淆作为主要安全边界；路径、签名、Hash、用户、父进程和系统权限必须共同参与判断。
6. 不使用“绝对无法破解”作为验收标准。
7. 开发计划中的验收项默认状态为“未验证”，完成测试后才能标记通过。
8. 每周必须提交可运行构建、自动化测试、手工测试记录、已知问题列表和回滚说明。

## 八、主要风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| WMI 事件丢失或监听断开 | 中 | 未授权软件短时运行 | 周期扫描、监听重建、启动扫描 |
| 短时程序在关闭前完成操作 | 中 | 存在绕过窗口 | 标准用户、服务 DACL、文件/注册表 ACL、高风险解释器限制 |
| 白名单误拦编译器子进程 | 高 | 无法正常上课 | 真实课程流程回归、规则版本化和快速回滚 |
| Agent 与 Service 通信漏洞 | 中 | 策略被伪造 | Pipe ACL、SID 校验、防重放 |
| 更新失败导致无法启动 | 中 | 严重 | A/B 目录、健康检查、自动回滚 |
| 安全模式配置错误 | 中 | 无法恢复 | 不破坏默认 SafeBoot，RecoveryTool |
| 代理受控降级影响上课 | 中 | 网络不可用 | 严格/宽松双模式、网站健康检测 |
| 键盘钩子影响 IDE | 高 | 教学受影响 | 模式化策略、Agent 独立、快速禁用 |
| 双进程重启风暴 | 中 | CPU 和日志异常 | 指数退避、阈值、Safe Degraded Mode |
| 日志加密后查询变慢 | 中 | 管理体验下降 | 索引与正文分离、批量解密 |
| BIOS 状态无法自动读取 | 高 | 误判设备安全 | 未知即人工核验，绝不默认通过 |
| 不同厂商 BIOS 菜单差异 | 高 | 部署成本增加 | 品牌差异表、标准检查单、现场记录 |
| 学生清除固件配置或拆机 | 低至中 | 外部启动重新开放 | 机房物理管理、封签、定期复检 |
| 不使用 BitLocker | 固有 | 成功离线访问后磁盘可被修改 | 明确边界、禁止外部启动、Secure Boot、物理管理 |
| Windows 更新造成兼容问题 | 中 | 服务异常 | 支持矩阵、自动恢复、灰度发布 |

## 九、Definition of Done

每个模块完成必须同时满足；DeviceSecurity 人工核验项也必须保存证据：

1. 代码已合并。
2. 单元测试通过。
3. 异常路径测试通过。
4. 权限边界测试通过。
5. 日志记录完整。
6. 有回滚或恢复方式。
7. 文档已更新。
8. 已知问题已登记。
9. 不依赖人工修改数据库或注册表才能正常运行。
10. 未完成验收项不得标记为通过。
