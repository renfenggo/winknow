## 背景

当前 Licensing 为内存模拟：令牌"签名"仅检查非空、动态码密钥由公开 DeviceId 派生、固定解锁码接受任意 ≥8 位字符串；IPC 管道 Everyone 可写且信任消息自报 `SenderSid`；进程按名放行、证书仅读 Subject；Recovery Vault 在清单缺失时可能把当前未知文件当作可信基线。

## 决策

### TD-04 授权模式

固定为**教师机 LAN 授权 + 学生机离线宽限**，云端保留接口但不进入发布范围：

- 教师侧持授权签名私钥（或调用受保护的本地签名服务）。
- 学生端只保存验证公钥和设备私有随机 Secret。
- 教师机签发短期签名 Token（含 ProductId、DeviceId、IssuedAt、ExpiresAt、PolicyVersion、Nonce、KeyId，RSA-PSS 或 ECDSA）。
- 网络不可达进入有限宽限；宽限结束显示锁屏，**不关闭安全管控服务**。
- 删除任意长度固定码与"从公开 DeviceId 派生 Secret"的代码；离线 Token 用 DPAPI 保存并防系统时间回拨。

### TD-05 IPC 身份

- 管道 ACL 创建时一次性设置：允许 SYSTEM、Administrators、Authenticated Users 以最小读写权限连接（管道 ACL 不支持按 SID 动态放行）。
- "已登记学生会话"准入在**应用层**完成：服务端从 Pipe Impersonation Token 取真实 SID，与会话登记表比对，不信任消息体 `SenderSid`（保留该字段仅作审计，必须与真实 SID 一致）。
- 首次连接握手绑定：协议版本、会话 ID、进程 ID、设备 ID、随机挑战（ClientNonce/ServerNonce）。
- RequestId 单调性以单连接（或协商后的连接会话）为范围，重连不永久误判。

### TD-06 代码与策略信任

- Windows 可执行文件使用 Authenticode，通过 `WinVerifyTrust` 校验（完整性、证书链、签名状态），不只读 Subject。
- 对端验证固定证书公钥哈希或明确的发布证书链。
- 更新包与策略使用独立 RSA/ECDSA 发布密钥签名；正式客户端不含任何生产签名私钥。
- 测试证书与正式证书的信任配置完全隔离。

### TD-08 Recovery Vault 信任来源

- 快照只能由**通过正式签名/Hash 验证的安装包**或**已提交成功的更新版本**建立。
- GuardService 不得在清单缺失时把当前未知文件自动视为可信基线。
- 快照刷新必须产生审计事件，保存来源版本与发布清单摘要。

## 理由

- 课堂场景（单教室、教师机在场）下 LAN 授权是成本最低的可信模型；签名 Token 使学生机离线期间可验证授权真伪。
- 连接层身份（Impersonation）是 Named Pipe 唯一不可伪造的身份来源；消息字段一律只作审计不作凭证。
- "当前文件即基线"等于允许攻击者篡改后自认证，必须禁止。

## 后果

- 需要一次密钥仪式：生成发布签名密钥对（更新包/策略/授权三类用途隔离），私钥仅存发布环境。
- 教师/AdminUI 侧需要持久化设备名单与私钥保护方案（PR-07 范围）。
- 所有现存模拟签名、固定码、DeviceId 派生密钥代码必须删除（不可保留为"后备路径"）。

## 被否决的替代方案

- HMAC 共享密钥授权：密钥需分发到所有学生机，一台被提取即全线失守，不如非对称签名。
- 信任自报 SID + 强化字段校验：任何消息字段都可通过写管道伪造，非身份边界。
