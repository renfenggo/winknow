# V7.0 威胁模型与安全边界

> **版本**：V7.0
> **状态**：第1周交付物
> **基线**：.NET 8.0 LTS、net8.0-windows、Windows 10/11 Pro 正式支持
> **编制日期**：2026-08-28

---

## 一、文档目的

本文档定义 Winknow V7.0 的威胁模型、攻击者等级（A1-A5）、安全边界和部署前提。

V7.0 的所有功能设计、权限设计、IPC 设计、自保护机制和部署检查都以本文档为依据。任何无法对应到本文档攻击者等级或安全边界的功能，均视为越界设计，不得纳入 V7.0 范围。

V7.0 明确不防护的攻击类型：
- **A4 离线物理攻击**：仅通过 BIOS/UEFI 限制提供"提高攻击成本"级别的防护，不承诺磁盘机密性
- **A5 国家级/高级持久威胁**：超出产品定位

---

## 二、攻击者等级定义（A1-A5）

### 2.1 等级总表

| 等级 | 攻击者画像 | 能力上限 | V7.0 防护目标 |
|------|-----------|---------|--------------|
| **A1** | 普通学生（无技术背景） | 点击界面、按快捷键、运行常见程序 | 完全阻止 |
| **A2** | 技术型学生（会编程、会批处理） | 自写程序、调用 Win32 API、修改用户层注册表 | 完全阻止 |
| **A3** | 进阶学生（会逆向、会调试） | 进程注入、DLL 劫持、调试器附加、用户层 Hook | 阻止 + 检测 + 审计 |
| **A4** | 拥有物理访问的攻击者 | U 盘启动、PE 启动、拆卸硬盘、离线注册表修改 | 提高成本，不承诺阻止 |
| **A5** | 国家级/高级持久威胁 | 内核漏洞、0day、固件级攻击 | 不在 V7.0 范围 |

### 2.2 A1 - 普通学生

**画像**：无技术背景的学生，通过 GUI 操作尝试绕过管控。

**能力上限**：
- 打开任务管理器（如未被禁用）
- 使用 Win+R 运行命令
- 修改用户层环境变量
- 运行浏览器访问任意网站
- 复制/移动文件

**V7.0 防护措施**：
- 任务管理器策略禁用（注册表 `DisableTaskMgr`）
- Run 键保护（仅学生用户无写入权限）
- 软件白名单（默认只允许白名单程序运行）
- 网站白名单（默认只允许白名单域名）
- USB Mass Storage 禁用
- 高风险解释器黑名单（powershell.exe、wscript.exe 等）

**防护目标**：完全阻止。

### 2.3 A2 - 技术型学生

**画像**：会编程、会写批处理、了解 Win32 API 基础的学生。

**能力上限**：
- A1 全部能力
- 自写 C/C++、C#、Python 程序并运行
- 调用 Win32 API（CreateProcess、OpenProcess、TerminateProcess）
- 修改 `HKEY_CURRENT_USER` 下任意键值
- 使用 `cmd.exe` 执行管道命令
- 复制系统自带工具到白名单目录外改名运行

**V7.0 防护措施**：
- 学生输出目录限制（仅 `C:\Users\*\source\repos\**` 等目录可执行学生编译产物）
- 进程综合判断（路径 + 签名 + Hash + 用户 + 父进程 + 命令行）
  > 注：进程名不能作为唯一放行依据
- WMI `ProcessStartTrace` 实时监听
- Service 启动全量进程扫描
- 1-2 秒周期进程扫描
- 命令行参数审计
- 父进程链校验（防止通过白名单程序拉起子进程）
- 用户层注册表关键键值监控与恢复

**防护目标**：完全阻止。

### 2.4 A3 - 进阶学生

**画像**：会逆向工程、会调试、了解 Windows 内部机制的学生。

**能力上限**：
- A2 全部能力
- 进程注入（CreateRemoteThread、SetWindowsHookEx）
- DLL 劫持（修改 PATH、放置恶意 DLL）
- 调试器附加（DebugActiveProcess）
- 用户层 API Hook（Inline Hook、IAT Hook）
- 内存修改（WriteProcessMemory）
- 自定义 Credential Provider（理论上可行，但 V7.0 不依赖此路径防护）
- 尝试停止服务（通过 SC 命令、PowerShell Stop-Service）

**V7.0 防护措施**：
- 数字签名验证（白名单程序必须签名匹配）
- Hash 验证（防止二进制被篡改）
- 服务 DACL 加固（仅 SYSTEM 和管理员可停止服务）
- 守护进程（GuardService 监控 ControlService 状态，被停止立即重启）
- 文件 ACL（程序目录仅 SYSTEM 和管理员可写）
- 注册表 ACL（关键键值仅 SYSTEM 和管理员可写）
- 代码签名验证（更新包、策略文件必须签名）
- 审计日志（所有可疑操作记录到 Windows Event Log 和 audit.db）
- 调试器检测（IsDebuggerPresent、PEB BeingDebugged）
- 注入检测（远程线程、新模块加载审计）

**防护目标**：阻止 + 检测 + 审计。即使攻击成功，也必须留下不可篡改的审计记录。

### 2.5 A4 - 拥有物理访问的攻击者

**画像**：能够物理接触学生机、持有 U 盘 PE 工具、可能拆卸硬盘的攻击者。

**能力上限**：
- A3 全部能力（在物理访问前或后）
- U 盘启动进入 PE 系统
- 外部光盘/USB 启动
- PXE 网络启动
- 拆卸硬盘离线挂载
- 离线注册表修改
- 离线文件替换
- Boot Menu 修改启动顺序
- 清除 CMOS（重置 BIOS）

**V7.0 防护措施**（仅"提高成本"级别，不承诺阻止）：

```
BIOS/UEFI 管理员密码
  + 关闭 USB Boot
  + 关闭 External Boot
  + 关闭 PXE
  + 限制 Boot Menu
  + 锁定 Boot Order
  + Secure Boot（必须开启）
  + 物理管理（机箱锁、教师巡视）
```

**明确的安全边界声明**：

> 由于 V7.0 不采用磁盘全盘加密（不使用 BitLocker），如果攻击者已经：
> - 绕过 BIOS/UEFI 启动限制；或
> - 拆卸硬盘；或
> - 通过其他方式获得离线磁盘访问；
>
> V7.0 **不承诺**磁盘文件、离线注册表和程序目录无法被修改。

**防护目标**：提高攻击成本，依赖物理管理。A4 不属于 V7.0 可完全防护范围。

### 2.6 A5 - 国家级/高级持久威胁（不在范围）

**画像**：拥有 0day、内核漏洞、固件级攻击能力的对手。

**V7.0 不防护**：A5 超出产品定位。V7.0 面向编程课堂环境，不与国家级对手对抗。

## 三、安全边界

### 3.1 V7.0 承诺的边界

| 边界类型 | 是否承诺 | 说明 |
|---------|---------|------|
| 在线运行时防护（A1-A3） | ✅ 承诺 | 标准用户权限 + 软件管控 + 服务加固 |
| 离线磁盘机密性 | ❌ 不承诺 | 不使用 BitLocker，离线挂载可修改 |
| SAS（Ctrl+Alt+Del）拦截 | ❌ 不尝试 | 不拦截 Secure Attention Sequence |
| 内核防护（A5） | ❌ 不在范围 | 不开发内核驱动 |

### 3.2 SAS（Ctrl+Alt+Del）处理边界

**V7.0 不尝试拦截 Ctrl+Alt+Del。**

Ctrl+Alt+Del 属于 Windows Secure Attention Sequence（SAS），由系统内核直接处理，用户层无法可靠拦截。

V7.0 不设计：
- 破解/Hook SAS
- GINA 劫持
- Credential Provider 劫持

V7.0 的安全不依赖拦截 SAS。系统通过以下机制保证学生即使进入 Windows 安全界面，也不能停止、修改或卸载核心管控服务：

```
标准用户权限
  + 任务管理器策略（DisableTaskMgr）
  + Service DACL（仅 SYSTEM 和管理员可停止）
  + 文件 ACL（程序目录仅 SYSTEM 和管理员可写）
  + 注册表 ACL（关键键值仅 SYSTEM 和管理员可写）
  + 软件管控（任务管理器、sc.exe、PowerShell Stop-Service 均受控）
  + 安全 IPC（管理命令必须签名 + 防重放）
```

### 3.3 离线攻击边界（A4）

V7.0 对 A4 离线攻击的主要防护链：

```
[物理层]  机箱锁 + 教师巡视
   ↓
[固件层]  BIOS/UEFI 管理员密码
   ↓
[启动限制] 关闭 USB Boot
          关闭 External Boot
          关闭 PXE
          限制 Boot Menu
          锁定 Boot Order
   ↓
[签名链]  Secure Boot（必须开启）
   ↓
[运行时]  ControlService + GuardService 守护
          文件 ACL
          注册表 ACL
          软件管控
```

**Secure Boot 状态处理**：

```
Secure Boot ON
  ↓
  DeviceSecurity 检测 → PASS
  ↓
  通过正式部署验收

Secure Boot OFF
  ↓
  DeviceSecurity 检测 → High Risk
  ↓
  设备不能通过正式部署验收
  ↓
  AdminUI 提示管理员整改

Secure Boot 状态未知（UNKNOWN）
  ↓
  DeviceSecurity 标记 UNKNOWN
  ↓
  不得默认为 PASS，必须人工核验
```

**原则**：可自动检测的自动检测；不能可靠检测的必须人工核验；任何未知状态不得默认为安全。

## 四、部署前提

V7.0 的安全模型依赖以下部署前提。任何前提不满足的设备，不得通过正式部署验收。

### 4.1 操作系统前提

| 项 | 要求 | 验证方式 |
|----|------|---------|
| 操作系统 | Windows 10 Pro 22H2+ 或 Windows 11 Pro | `winver` |
| 架构 | x64 | 系统属性 |
| 固件 | UEFI（非 Legacy BIOS） | `msinfo32` → BIOS 模式 |
| .NET Runtime | .NET 8.0 LTS | 安装程序检测 |
| 用户类型 | 标准用户（学生账户） | `net user <用户名>` |

**关键约束**：
- 学生账户必须是**标准用户**，不是管理员
- 不允许将学生账户加入 Administrators 组
- 不允许通过 UAC 让学生获得管理员权限

### 4.2 固件前提（BIOS/UEFI）

| 项 | 要求 | 验证方式 |
|----|------|---------|
| BIOS/UEFI 管理员密码 | 已设置 | 人工核验 |
| USB Boot | 关闭 | 人工核验 |
| External Boot | 关闭 | 人工核验 |
| PXE Boot | 关闭 | 人工核验 |
| Boot Menu | 限制或锁定 | 人工核验 |
| Boot Order | 锁定（首启动项为内置硬盘） | 人工核验 |
| Secure Boot | **必须开启** | DeviceSecurity 自动检测 |

**Secure Boot 是正式部署的硬性要求**：
- Secure Boot OFF → 标记 High Risk → 不能通过验收
- Secure Boot UNKNOWN → 不得默认 PASS，必须人工核验

### 4.3 不使用的技术

V7.0 明确不采用以下技术，部署时不应启用或配置：

| 技术 | 决策 | 原因 |
|------|------|------|
| BitLocker | **不使用** | V7.0 不开发 BitLocker 管理能力，不作为部署前提、验收项或可选模块 |
| AppLocker | **不使用** | 版本依赖问题，V7.0 采用自研软件管控引擎 |
| WFP/驱动方案 | **不使用** | 属于后续版本，V7.0 不开发内核驱动 |
| SAS 拦截 | **不尝试** | 见 3.2 节 |

### 4.4 代码签名前提

**开发阶段（第1-6周）**：
- 使用 Self-Signed Test Certificate 或内部测试证书
- 用于：文件签名、签名验证、更新包签名、TrustedUpdater、Policy Signature、A/B Update 验证
- 正式公开代码签名证书尚未到手**不得阻塞**第1-6周开发

**正式发布阶段**：
- 使用合法 Public Code Signing Certificate
- 正式签名私钥必须位于：Hardware Token、HSM、Cloud HSM 或合规托管签名服务
- **禁止**：
  - 把 Production Private Key 作为普通 PFX 长期放在开发电脑
  - 把私钥提交 Git
  - 把私钥明文放进 CI
  - 把私钥放在学生端

**学生端只保存**：Public Key / Certificate Chain，用于验证。

**正式证书最迟要求**：第7周 TrustedUpdater / 安全更新进入正式签名集成阶段前必须具备可用签名方案。

## 六、威胁模型与组件映射

| 组件 | 主要应对的攻击者等级 | 关键职责 |
|------|---------------------|---------|
| ControlService | A1-A3 | 软件管控、网络管控、USB 管控、策略执行 |
| GuardService | A2-A3 | 守护 ControlService、被停止立即重启 |
| SessionAgent | A1-A3 | 用户会话内交互、键盘钩子、屏幕控制 |
| AdminUI | 管理员 | 策略下发、设备核验、日志查看 |
| TrustedUpdater | A3 | 签名更新、A/B 部署、自动回滚 |
| RecoveryTool | 管理员 | 离线授权、维护模式、紧急恢复 |
| DeviceSecurity | A4 | Secure Boot 检测、BIOS 配置核验、设备评分 |
| Winknow.Security | A3 | DPAPI、AES-256-GCM、Hash Chain |
| Winknow.Logging | A3 | 审计日志完整性、防篡改 |

## 七、安全边界检查清单

部署前必须完成以下检查，全部通过方可正式部署：

### 7.1 操作系统检查
- [ ] Windows 10 Pro 22H2+ 或 Windows 11 Pro
- [ ] x64 架构
- [ ] UEFI 固件模式
- [ ] .NET 8.0 Runtime 已安装
- [ ] 学生账户为标准用户（非管理员）

### 7.2 固件检查
- [ ] BIOS/UEFI 管理员密码已设置
- [ ] USB Boot 已关闭
- [ ] External Boot 已关闭
- [ ] PXE Boot 已关闭
- [ ] Boot Menu 已限制或锁定
- [ ] Boot Order 已锁定
- [ ] **Secure Boot 已开启**（硬性要求）

### 7.3 软件检查
- [ ] Winknow V7.0 已安装并签名验证通过
- [ ] ControlService 运行中
- [ ] GuardService 运行中
- [ ] 默认策略已下发
- [ ] 软件白名单已配置（VS Code、Dev-C++ 等）
- [ ] 网站白名单已配置（luogu.com.cn 等）

### 7.4 不应存在的配置
- [ ] 未启用 BitLocker（V7.0 不依赖）
- [ ] 未启用 AppLocker（V7.0 不依赖）
- [ ] 学生账户未在 Administrators 组
- [ ] 学生账户无 Stop-Service 权限
