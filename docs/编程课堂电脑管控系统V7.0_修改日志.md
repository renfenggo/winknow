## 二、V7.0 必须完整继承的 V6.0 优势

此前的简化版 V7.0 删除了 V6.0 的大量成熟设计，属于版本倒退。本次正式修订明确以下内容必须全部保留。

### 2.1 A1-A5 威胁模型

| 等级 | 能力 | V7.0 目标 |
|------|------|-----------|
| A1 | 普通学生、标准用户 | 必须阻止常见绕过 |
| A2 | 会编程和使用脚本的学生 | 必须阻止常见绕过并记录 |
| A3 | 拥有本地管理员权限 | 不承诺绝对阻止，必须审计和恢复 |
| A4 | U 盘 PE、外部启动等离线攻击 | 通过 BIOS/UEFI 与启动策略降低风险 |

- 不使用 BitLocker，因此不承诺攻击者成功获得离线磁盘访问后仍无法修改磁盘。
- 普通学生账户必须为标准用户。

## 三、修改 1：删除 AppLocker 依赖

### V6.0 原设计

AppLocker 作为主要应用控制，WMI 作为记录和兜底。

### V7.0 正式设计

完全不依赖 AppLocker，采用：

```text
WMI 实时监听
+
Service 启动全量扫描
+
每 1～2 秒周期扫描
+
路径、签名、Hash、用户、父进程、命令行联合判断
+
标准用户权限
+
服务、文件和注册表 ACL
```

### 修改原因

1. 降低部署和策略维护复杂度。
2. 避免编程环境中编译器、调试器、扩展宿主和学生输出程序被大量误拦。
3. 不把产品绑定到 AppLocker 策略管理。
4. 更符合 10～50 台培训机构电脑的第一阶段部署能力。

### 能力边界

- V7.0 可以快速发现并关闭未授权程序。
- V7.0 不承诺在程序第一条指令执行前完成阻止。
- 短时程序风险依赖标准用户权限、服务 DACL、文件 ACL 和高风险解释器限制共同降低。

## 四、修改 2：WMI 软件管控增强

新增以下要求：

1. WMI 监听断线自动恢复。
2. Service 启动立即扫描已有进程。
3. 周期扫描弥补事件丢失。
4. 进程名不作为唯一规则。
5. 子进程不得自动继承父进程白名单。
6. 学生输出程序只能在受控目录和规则范围内运行。
7. Dev-C++、VS Code、编译器、调试器和语言服务建立完整进程链测试。
8. 高风险解释器默认禁止或严格限制。
9. 关闭失败升级为高风险事件。
10. 规则版本化并支持回滚。

## 五、修改 3：不采用 BitLocker

### 决策

V7.0 不将 BitLocker 作为产品要求、可选模块或验收项。

### 原因

1. 增加恢复密钥管理成本。
2. 培训机构可能缺乏统一设备和密钥管理能力。
3. 错误管理恢复密钥可能导致数据无法访问。
4. 当前目标优先解决普通学生通过 U 盘 PE 启动的问题。

### 替代措施

- BIOS/UEFI 管理员密码；
- 禁止 USB Boot；
- 禁止 External Device Boot；
- 禁止 PXE/Network Boot；
- 锁定 Boot Order；
- 限制一次性 Boot Menu；
- 开启 Secure Boot；
- Windows 中禁用 USB 大容量存储；
- 学生标准用户；
- 机房物理管理和定期复检。

### 剩余风险

不使用 BitLocker 意味着：

> 如果攻击者已经成功绕过固件限制、拆卸硬盘或获得离线磁盘访问，V7.0 不保证磁盘文件、离线注册表和程序目录仍无法被修改。

该边界必须写入产品文档、部署手册和风险提示，不能隐瞒。

## 六、修改 4：新增 DeviceSecurity Module

### 职责

- Secure Boot 状态检测；
- UEFI/Legacy 模式识别；
- 固件厂商、型号和版本采集；
- 可识别启动项采集；
- BIOS/UEFI 人工核验清单；
- USB Boot、External Boot、PXE、Boot Order、Boot Menu 检查；
- 设备安全评分；
- 设备部署报告；
- 固件变化后核验失效。

### 设计原则

> 可自动读取的项目自动读取；不能可靠读取的项目必须标记为“需人工核验”，绝不能默认显示为安全。

建议权重：

| 检查项 | 权重 |
|--------|------|
| 学生标准用户 | 20 |
| BIOS/UEFI 管理员密码 | 20 |

| Boot Order/Boot Menu 限制 | 10 |

- 90～100：低风险；

- 60～74：高风险；
- 60 以下：禁止标记为合格。

## 九、修改 7：移动存储与外部启动分层

### Windows 运行期间

由产品控制：

- U 盘；
- 移动硬盘；
- USB 大容量存储；
- 插拔日志；
- 管理员临时授权；
- 键鼠和必要 HID 放行。

### Windows 启动之前

由部署规范控制：

- BIOS/UEFI 密码；
- 禁止 USB/外部/PXE 启动；
- 锁定启动顺序；
- 限制启动菜单；
- Secure Boot。

### 修改原因

Windows 中禁用 USBSTOR 只能在 Windows 启动后生效，不能阻止固件在开机阶段从 U 盘启动 PE。

## 十三、正式决策记录

### 决策 1：V7.0 不得删除 V6.0 成熟能力

V7.0 的设备安全属于增量模块，不能替代威胁模型、IPC、更新回滚、隐私、密钥、风险和验收体系。

### 决策 2：不采用 AppLocker

基础版统一采用 WMI + 启动扫描 + 周期扫描，并明确执行窗口风险。

### 决策 3：不采用 BitLocker

优先通过固件启动限制解决普通学生使用 U 盘 PE 的风险，同时公开剩余风险。

### 决策 4：未知 BIOS 状态不得默认为安全

任何不能可靠自动读取的固件项目必须由管理员人工核验。

### 决策 5：V7.0 发布必须包含真实设备记录

不能只在虚拟机或单一品牌电脑完成验收；正式灰度至少覆盖 10 台电脑和 3 类品牌或主板系列。

### 决策 6：V7.0 不采用 AppLocker（重申）

V7.0 基础版统一采用 WMI + 启动扫描 + 周期扫描。禁止重新加入 AppLocker。AppLocker 的 Windows 版本依赖（仅 Enterprise/Education）不适合培训机构客户群体。

### 决策 7：V7.0 不采用 BitLocker（重申）

V7.0 不依赖 BitLocker。不开发 BitLocker 管理能力。BitLocker 不属于部署前提、验收项或可选模块。V7.0 对 A4 离线攻击的主要防护是 BIOS/UEFI 管理员密码 + 关闭 USB Boot + 关闭 External Boot + 关闭 PXE + 限制 Boot Menu + 锁定 Boot Order + Secure Boot + 物理管理。

### 决策 8：Secure Boot 为正式部署要求

Secure Boot 从"建议启用"升级为"必须开启"。程序运行逻辑：Secure Boot OFF → DeviceSecurity 检测 → 标记 High Risk → 设备不能通过正式部署验收 → AdminUI 提示管理员整改。无法检测状态时标记为 UNKNOWN，不得默认为 PASS。
