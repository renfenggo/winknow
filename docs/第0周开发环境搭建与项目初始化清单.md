## 零、代码签名方案（项目前置条件，第0周启动）

> 代码签名是 V7.0 安全更新、A/B 部署、TrustedUpdater 和策略文件验证的硬前置条件。本节定义开发阶段和正式发布阶段的签名方案。

### 开发阶段（第 1～6 周）

使用 **Self-Signed Test Certificate** 或内部测试代码签名证书，用于提前开发和测试：
- 文件签名
- 签名验证
- 更新包签名
- TrustedUpdater 流程
- Policy Signature
- A/B Update 验证

> 正式公开代码签名证书尚未到手**不得阻塞**第 1～6 周开发。

### 正式发布阶段

使用合法 **Public Code Signing Certificate**。

正式签名私钥必须位于：
- Hardware Token，或
- HSM，或
- Cloud HSM / 合规托管签名服务

**禁止**：
- 把 Production Private Key 作为普通 PFX 长期放在开发电脑
- 把私钥提交 Git
- 把私钥明文放进 CI
- 把私钥放在学生端

学生端只保存 **Public Key / Certificate Chain** 用于验证。

### 第 0 周任务

- [ ] 确定正式代码签名方案（OV 或 EV，签名服务选型）

### 正式证书最迟要求

正式证书必须在 **第 7 周 TrustedUpdater / 安全更新进入正式签名集成阶段前**具备可用签名方案。

### 3.3 DeviceId.cs

路径：`src/Winknow.Core/DeviceId.cs`
```csharp
using System.Security.Cryptography;
using System.Text;

namespace Winknow.Core;

public static class DeviceId
{
    public static string Generate()
    {
        var parts = new List<string>();
        
        try
        {
            using var key = Microsoft.Win32.Registry.LocalMachine.OpenSubKey(
                @"SOFTWARE\Microsoft\Cryptography");
            if (key?.GetValue("MachineGuid") is string guid)
                parts.Add(guid);
        }
        catch { }
        
        try
        {
            using var key = Microsoft.Win32.Registry.LocalMachine.OpenSubKey(
                @"HARDWARE\DESCRIPTION\System\CentralProcessor\0");
            if (key?.GetValue("ProcessorNameString") is string cpu)
                parts.Add(cpu);
        }
        catch { }
        
        if (parts.Count == 0)
            parts.Add(Guid.NewGuid().ToString());
        
        var combined = string.Join("|", parts);
        var hash = SHA256.HashData(Encoding.UTF8.GetBytes(combined));
        return Convert.ToHexString(hash).Substring(0, 16);
    }
}
```

using System.Security.Cryptography;
using System.Text;

namespace Winknow.Core;

public static class SecurityUtils
{
    public static string ComputeSha256Hash(byte[] data)
    {
        var hash = SHA256.HashData(data);
        return Convert.ToHexString(hash);
    }
    
    public static string ComputeSha256Hash(string text)
    {
        var bytes = Encoding.UTF8.GetBytes(text);
        return ComputeSha256Hash(bytes);
    }
    
    public static string ComputeSha256HashFile(string filePath)
    {
        using var stream = File.OpenRead(filePath);
        var hash = SHA256.HashData(stream);
        return Convert.ToHexString(hash);
    }
    
    public static byte[] GenerateRandomBytes(int count)
        => RandomNumberGenerator.GetBytes(count);
    
    public static byte[] GenerateNonce()
        => GenerateRandomBytes(16);
}

## 六、常见问题

**Q1：dotnet new worker 创建的项目如何转换为 Windows Service？**

在 Program.cs 中添加：
```csharp
using Microsoft.Extensions.Hosting.WindowsServices;

HostApplicationBuilder builder = Host.CreateApplicationBuilder(args);

builder.Services.AddWindowsService(options =>
{
    options.ServiceName = "Winknow Control Service";
});

builder.Services.AddHostedService<Worker>();

IHost host = builder.Build();
host.Run();
```

GuardService 同样使用 `AddWindowsService()` 扩展方法，不要使用已过时的 `builder.Host.UseWindowsService()`。

**Q2：WPF项目需要额外配置吗？**

默认模板即可，但需要添加对 `Winknow.Core` 的引用。确保输出类型为 `WinExe`。

**Q3：SessionAgent 是否应该使用 Worker 模板？**

建议改为控制台应用 (`dotnet new console`)，因为它需要前台交互（键盘钩子）。最终发布时仍需作为无窗口进程运行，可配置输出类型为 `WinExe`。

**Q4：如何处理不同开发机器的路径差异？**

所有代码中禁止硬编码绝对路径。使用 `Environment.GetFolderPath()`、`Path.Combine()` 和 `AppContext.BaseDirectory`。
