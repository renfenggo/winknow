# 编程课堂电脑管控系统 V7.0 产品需求文档

> **版本**：V7.0 软件与设备安全增强版  
> **基线**：V6.0 架构与可维护性增强版  
> **核心目标**：完整继承 V6.0 的威胁模型、安全边界、六组件架构、安全 IPC、更新回滚、可信恢复、日志完整性、密钥管理、隐私治理、失败策略与验收体系；在此基础上新增设备启动安全、移动存储强化和设备安全检查，降低通过 U 盘 PE、外部启动和错误 BIOS/UEFI 配置绕过 Windows 管控的风险。

---

## 一、产品定位

V7.0 继续坚持“更难被结束”，而是把系统升级为具备明确安全边界、稳定运行能力和可恢复能力的正式产品版本。

| 版本 | 定位 | 核心能力 |
|------|------|----------|
| V4.0 | 基础管控版 | 软件白名单、网站白名单、USB 管理、基础日志 |
| V5.0 | 安全增强版 | 进程/服务保护、防卸载、注册表保护、双进程守护、日志加密 |
| V6.0 | 架构与可维护性增强版 | 威胁模型、Service + Session Agent、安全 IPC、安全更新、恢复、密钥管理、网络防绕过、隐私治理 |
| **V7.0** | **软件与设备安全增强版** | **完整继承 V6.0 + WMI 软件管控增强 + BIOS/UEFI 部署规范 + 外部启动防护 + Secure Boot 检测 + 设备安全评分** |

V7.0 的产品目标：

1. 普通学生不能通过任务管理器、命令行、PowerShell、服务管理器、允许的编程工具或修改常见配置长期绕过管控；未授权程序由 WMI 实时监听、启动扫描和周期扫描快速发现并关闭。
2. 管控系统出现故障时，授权管理员可以安全进入维护模式并完成修复。
3. 软件升级失败时可以自动回滚，不得导致学生电脑永久锁死。
4. 核心策略和密钥不得以明文方式存储在学生端。
5. 网络、应用、日志和恢复机制均必须具备明确的失败策略。
6. 形成可测试、可验收、可灰度部署的正式交付标准。
7. 通过 BIOS/UEFI 管理员密码、禁止 USB/外部/PXE 启动、锁定启动顺序和 Secure Boot 状态检查，降低 PE 离线绕过风险。
8. V7.0 不依赖 AppLocker，也不强制使用 BitLocker；文档必须明确相应的能力边界。

## 二、安全原则

### 2.1 安全边界原则

V7.0 不使用“任何手段都无法终止”“绝对无法破解”等不可验证表述。

产品承诺限定在明确的威胁模型内：

- 标准用户权限下必须阻止常见绕过。
- 本地管理员、SYSTEM、离线启动、内核级攻击不承诺绝对阻止。
- 对超出产品能力边界的攻击，系统应记录、告警、恢复，或依赖 BIOS/UEFI 管理员密码、外部启动限制、Secure Boot、机房物理管理等外部措施。
- V7.0 不采用 BitLocker，因此不承诺在攻击者已成功进入外部系统、拆卸硬盘或获得离线磁盘访问能力后仍能保护磁盘内容。

### 2.2 可维护原则

安全功能不得阻止正式更新、授权卸载、故障恢复和管理员维护。

### 2.3 最小权限原则

- ControlService 使用 LocalSystem 运行。
- SessionAgent 使用当前登录学生账户运行。
- AdminUI 仅在需要修改系统策略时请求管理员提权。
- Updater 仅在受信任维护流程中获得替换核心文件的权限。
- 普通学生账户不得拥有本地管理员权限。

### 2.4 默认安全原则

- 未明确允许的软件由软件管控引擎快速检测并关闭；由于不使用 AppLocker，V7.0 不承诺在程序执行第一条指令前完成阻止。
- 未明确允许的网站默认禁止。
- 核心策略损坏时使用最后可信策略。
- 本地代理或关键模块失效时按策略进入受控降级，而不是自动全部放行。

## 三、威胁模型与安全边界

### 3.1 攻击者等级

| 等级 | 攻击者能力 | V6.0 处理目标 |
|------|------------|---------------|
| A1 普通学生 | 标准账户，只会使用图形界面 | 必须阻止绕过 |
| A2 技术型学生 | 标准账户，会使用 IDE、脚本、命令行和常见工具 | 必须阻止常见绕过并记录 |
| A3 本地管理员 | 拥有管理员密码或管理员令牌 | 不承诺绝对阻止；必须提供审计和恢复 |
| A4 离线攻击 | 使用 PE、U 盘启动、移动硬盘启动或修改启动顺序 | 通过 BIOS/UEFI 管理员密码、禁止 USB/外部/PXE 启动、锁定启动顺序和 Secure Boot 降低风险；不使用 BitLocker，不承诺磁盘离线机密性 |
| A5 内核级攻击 | 自带驱动、利用内核漏洞 | 不属于 V7.0；后续 WFP/驱动版本处理 |

### 3.2 产品部署前提

1. 学生使用标准用户账户。
2. 管理员密码不得告知学生。
3. BIOS/UEFI 设置管理员密码。
4. 禁止未授权外部启动设备。
5. Secure Boot 必须开启。
6. 系统版本必须在产品支持矩阵内。
7. 安装和更新过程必须由授权管理员执行。

## 五、核心功能需求

### 5.1 Service 与 Session Agent 分离

**需求描述**：Windows Service 不直接承担用户桌面交互。键盘钩子、前台窗口识别和学生提示必须由 SessionAgent 在学生交互会话中完成。

功能要求：

1. 用户登录后，ControlService 自动启动对应 SessionAgent。
2. 多用户登录时，每个活动会话只运行一个 Agent。
3. 用户注销后，Agent 自动退出。
4. Agent 被异常结束后，ControlService 在受限重试策略下恢复。
5. Agent 不得直接写入系统策略。
6. Agent 所有敏感操作必须通过安全 IPC 请求 Service。
7. Service 不依赖 Agent 才能维持软件白名单、USB、注册表和网络核心策略。

验收标准：

- 学生登录后 5 秒内 Agent 正常启动。
- Agent 被结束后，核心软件管控仍然生效。
- Agent 重启不影响 ControlService。
- 多会话环境中不存在重复 Agent 或跨会话控制错误。

### 5.2 安全 IPC

1. 使用 Named Pipe 或等效本地 IPC。
2. Pipe ACL 只允许 SYSTEM、管理员和指定当前会话用户连接。
3. 每条消息包含协议版本、消息类型、请求编号、时间戳、随机数和设备标识。
4. 管理类命令必须进行调用方身份校验。
5. 拒绝重复消息、过期消息和未知命令。
6. IPC 异常不得导致 Service 崩溃。
7. 日志中不得记录密码、密钥和完整授权码。

验收标准：

- 普通学生不能通过自写程序调用管理接口修改策略。
- 重放历史维护命令无效。
- 非法消息触发审计记录但不导致服务退出。

### 5.3 软件管控引擎（WMI + 启动扫描 + 周期扫描）

#### 需求描述

V7.0 不依赖 AppLocker。系统采用 Windows Service、WMI 进程创建事件、服务启动时全量扫描和周期扫描组成基础软件管控引擎。

此方案属于“程序创建后快速检测并关闭”，不是内核级或执行前阻止机制。产品文档和销售说明不得承诺“未授权程序一行代码都不能执行”。

#### 功能要求

1. 使用 `Win32_ProcessStartTrace` 或等效 WMI 事件监听新进程。
2. ControlService 启动时立即扫描当前已存在的全部进程。
3. 每 1～2 秒执行一次轻量级进程复查，弥补 WMI 事件丢失、监听重连和服务重启窗口。
4. 对每个新进程综合校验：
   - 进程名；
   - 规范化完整路径；
   - 文件数字签名及发布者；
   - 文件 Hash；
   - 运行用户 SID；
   - 父进程；
   - 命令行参数；
   - 策略版本。
5. 进程名不能作为唯一放行依据。
6. 白名单进程产生的子进程必须重新校验，不能自动继承父进程权限。
7. 对频繁升级且签名稳定的软件，优先采用发布者 + 路径规则。
8. 对无签名、固定版本的软件，采用路径 + Hash 规则。
9. 对学生编译产生的程序，支持受控工作目录和有效期规则：
   - 仅允许从指定项目输出目录启动；
   - 仅允许当前学生账户；
   - 可限制父进程为指定 IDE/编译器；
   - 记录生成和运行事件。
10. 默认禁止或严格限制高风险解释器和系统工具，例如 PowerShell、WScript、CScript、MSHTA、注册表编辑器和服务控制工具。
11. 命令行关键字检测只作为辅助信号，不能替代服务 DACL、文件 ACL 和注册表权限。
12. WMI 监听断开时自动重建，并在恢复前依靠周期扫描继续工作。
13. 非授权进程关闭后记录：
   - PID；
   - 名称；
   - 路径；
   - Hash；
   - 用户；
   - 父进程；
   - 命令行摘要；
   - 发现时间；
   - 关闭结果；
   - 策略版本。
14. 关闭失败时升级为高风险事件，由 GuardService 和权限模块继续处理。
15. 软件默认白名单不可删除；管理员自定义规则可以添加、禁用、删除和回滚。

#### 基础性能目标

- 普通桌面软件：目标在启动后 1 秒内发现并处理。
- WMI 事件丢失：周期扫描目标在 2 秒内发现。
- Service 重启：完成初始化后立即扫描已有进程。
- 扫描不得导致空闲 CPU 长期高于性能目标。

#### 验收标准

- [ ] 未授权普通桌面软件启动后在目标时间内被关闭。
- [ ] 将未知程序改名为 `Code.exe` 不能绕过路径、签名或 Hash 检查。
- [ ] VS Code、Dev-C++ 启动的子进程会被重新检查。
- [ ] 学生编译的程序仅在受控目录和规则范围内运行。
- [ ] WMI 监听停止后，周期扫描仍能发现未授权程序。
- [ ] WMI 恢复后不会产生重复监听器或重复日志。
- [ ] 关闭失败会形成高风险日志，不会静默忽略。
- [ ] 所有规则变更可以回滚到最后可信版本。

### 5.4 进程与服务保护修订

1. ControlService 和 GuardService 设置合理的服务 DACL。
2. 标准用户不得停止、暂停、修改或删除服务。
3. 普通管理工具不得获得 `PROCESS_TERMINATE` 权限。
4. 使用 SCM Failure Actions 作为第一层服务恢复。
5. GuardService 作为第二层恢复机制。
6. 禁止因调试器检测而主动反复退出核心 Service。
7. 调试器进程名仅作为风险信号，不作为安全边界。
8. 检测异常时提高日志等级、限制敏感管理操作并触发告警。
9. 本地管理员和 SYSTEM 权限不纳入“绝对无法停止”承诺。

### 5.5 安全模式与恢复通道

1. 不删除、不破坏 Windows 默认 SafeBoot 结构。
2. 将必要服务正确登记到 Minimal 和 Network 安全模式配置。
3. 保护本产品对应 SafeBoot 项不被删除。
4. 保留 Windows 恢复环境。
5. 提供受签名保护的 RecoveryTool。
6. 恢复工具支持恢复最后可信配置、恢复上一个程序版本、修复服务注册、解除异常维护锁和导出诊断日志。
7. 恢复操作必须验证管理员身份或一次性恢复密钥。
8. 所有恢复操作记录审计信息。

### 5.6 安全维护与卸载

1. 管理员密码验证。
2. 支持离线 TOTP 或一次性恢复密钥。
3. 管理员密码使用带盐慢 Hash 保存，不保存明文。
4. 维护模式具有明确有效期，默认不超过 15 分钟。
5. 维护模式记录启动人、时间、原因、操作和结束时间。
6. 授权卸载必须通过 TrustedUpdater 或签名卸载器完成。
7. 直接删除安装目录失败。
8. 维护超时后自动恢复保护。
9. 紧急恢复密钥只能使用一次。
10. 后续云端上线后可增加在线授权码，但不能取消离线维护能力。

### 5.7 安全更新、A/B 部署与回滚

1. 更新包必须具有产品数字签名。
2. 客户端只内置验证公钥，不保存签名私钥。
3. 更新前验证签名、产品标识、目标版本、文件 Hash 和最低可升级版本。
4. 使用 Current、Previous、Staging 三个目录。
5. 更新流程包含验证、暂存、维护、切换、健康检查、提交和失败回滚。
6. 防止降级到已知不安全版本。
7. 数据库升级必须支持迁移和回滚。
8. 主服务、守护服务和 Agent 版本必须进行兼容性校验。
9. 更新过程不得无限触发双进程互相拉起。
10. 保留最近一个稳定版本和恢复副本。

### 5.8 网络防绕过

1. 监控 HKCU 和 HKLM 代理设置。
2. 代理配置每 20 秒校验一次，同时支持变更事件触发即时检查。
3. 检查并保护 ProxyEnable、ProxyServer、AutoConfigURL、PAC 文件及其 Hash 和签名。
4. 监控 DNS 配置异常。
5. IPv4 与 IPv6 使用一致策略。
6. 检测常见 VPN、TUN、虚拟网卡和代理软件。
7. 浏览器使用企业策略锁定代理和安全 DNS 设置。
8. 本地代理失效时必须按严格模式或宽松模式执行，不允许静默全部放行。
9. 默认网站包必须包含主域名、必要子域名、CDN、静态资源、API、登录和提交依赖。
10. 系统默认网站规则不可删除。
11. 管理员可增加自定义网站包。
12. 提供站点健康检测，验证登录、图片和代码提交等关键流程。

### 5.9 键盘策略模式

| 按键 | 普通学习模式 | 严格考试模式 |
|------|--------------|--------------|
| Ctrl+Shift+Esc | 禁止 | 禁止 |
| Win+R | 禁止 | 禁止 |
| Win+X | 禁止 | 禁止 |
| Win+D | 可配置 | 禁止 |
| Alt+Tab | 允许授权应用切换 | 限制为授权窗口 |
| Alt+F4 | 允许正常关闭授权程序 | 按窗口策略限制 |
| Ctrl+C/V/Z | 允许 | 允许 |
| Ctrl+Alt+Delete | 不作为普通钩子可拦截项 | 通过系统策略处理相关入口 |

键盘钩子必须运行在 SessionAgent。Agent 崩溃时不得导致键盘永久失效。

### 5.10 文件完整性与可信恢复

1. 核心文件使用 SHA-256 和数字签名校验。
2. 配置和策略使用签名验证。
3. 文件目录采用 Current、Previous、Recovery。
4. Current 损坏时由 GuardService 从可信副本恢复并重新启动。
5. 不将 .NET 托管代码内存段 Hash 作为 V7.0 核心安全边界。
6. 混淆器必须兼容 .NET 8，并通过完整回归测试。
7. 不允许把密钥硬编码在程序集内。

### 5.11 守护与重启风暴保护

1. 主服务和守护服务使用心跳租约，而不是只检查进程名。
2. 使用单实例 Mutex。
3. 校验对方进程路径、签名、版本和 Hash。
4. 支持指数退避。
5. 设置单位时间最大重启次数。
6. 连续崩溃超过阈值后进入 Safe Degraded Mode。
7. 更新和维护期间暂停交叉拉起。
8. 重启原因、次数和间隔必须记录。
9. 优先使用 SCM Failure Actions 恢复服务。

### 5.12 日志加密与完整性

1. 事件内容使用 AES-256-GCM 加密。
2. 每台设备使用独立日志密钥。
3. 日志密钥使用 DPAPI Machine Scope 封装。
4. 日志采用追加写入。
5. 每条记录关联前一条记录 Hash。
6. 每固定数量记录生成签名检查点。
7. 最新检查点保存到独立受保护位置。
8. 关键事件同时写入 Windows Event Log。
9. 日志删除、截断和完整性异常必须单独告警。
10. 导出 CSV 时显示完整性状态。
11. SQLite 保存索引和查询字段，敏感事件正文加密保存。

### 5.13 密钥与凭据管理

1. 产品签名私钥只存在于受控构建环境。
2. 学生端仅保存验证公钥。
3. 每台设备生成独立日志密钥。
4. 管理员密码使用 Argon2id、PBKDF2 或等效慢 Hash。
5. 密钥具备版本号并支持轮换。
6. 恢复码一次性使用并记录使用状态。
7. 密钥、密码和授权码不得写入普通日志。
8. 设备重装、转移和报废必须有密钥清理流程。

### 5.14 隐私与数据保留

默认收集：设备 ID、学生标识、进程名、程序路径、发布者、Hash、网站域名、时间、策略版本和处理结果。

默认不收集：网页正文、表单内容、账号密码、学生输入内容、学生代码正文、聊天内容和 HTTPS 页面完整内容。

1. 默认只记录域名，不记录包含敏感查询参数的完整 URL。
2. 默认日志保留 30 天，可配置。
3. 超期日志自动安全删除。
4. 只有授权管理员可查看和导出。
5. 设备转给新学生前可以清除旧学生关联数据。
6. 导出行为必须记录审计日志。

### 5.15 系统兼容性

V7.0 正式支持环境：

- **Windows 10 Pro 22H2+**（仍在微软支持周期内）
- **Windows 11 Pro**
- 架构：x64
- 固件：UEFI

不建议部署：

- 已退出微软安全支持且没有 ESU 的 Windows 10

重点测试范围：

- Windows 更新前后；
- 多语言、多用户、不同 DPI；
- 常用 IDE、编译器和浏览器；
- 杀毒软件共存；
- 睡眠、休眠、快速启动、异常断电；
- 无网络状态。

### 5.16 失败策略与安全降级

| 故障 | 默认处理 |
|------|----------|
| 策略文件损坏 | 使用最后可信策略 |
| 软件管控策略异常 | 回滚到上一版本 |
| SessionAgent 崩溃 | 核心管控继续，受限重启 Agent |
| 本地代理崩溃 | 按严格/宽松模式执行，不静默全放行 |
| 日志写入失败 | 写入 Windows Event Log 并告警 |
| 更新失败 | 自动回滚 Previous |
| 主程序损坏 | 从 Recovery 恢复 |
| 守护重启过多 | 进入 Safe Degraded Mode |
| 密钥不可解密 | 停止敏感导出，保留核心管控并提示维护 |
| 管理员配置错误 | 支持一键恢复系统默认策略 |

### 5.17 设备启动安全与 DeviceSecurity 模块

#### 需求描述

V7.0 在 V6.0 软件安全体系之上增加设备启动安全。该模块不尝试用普通 Windows 软件直接修改所有厂商 BIOS/UEFI 设置，而是负责“可自动检测的自动检测、不能可靠检测的形成管理员核验清单”。

V7.0 不采用 BitLocker。设备启动安全目标是降低学生通过 U 盘 PE、移动硬盘、PXE 或启动菜单进入外部系统的可能性，而不是承诺攻击者获得离线磁盘访问后仍无法读取或修改磁盘。

#### 设备部署强制要求

1. 设置 BIOS/UEFI 管理员密码。
2. 学生不得知道 BIOS/UEFI 密码。
3. 禁止 USB Boot。
4. 禁止 External Device Boot。
5. 禁止 PXE/Network Boot。
6. 锁定 Boot Order，系统盘为唯一允许的正常启动入口。
7. 关闭或限制一次性 Boot Menu；无法关闭时应确认其中不存在外部启动项。
8. 开启 Secure Boot。
9. Windows 运行期间继续禁用 USB 大容量存储，保留键盘、鼠标等必要 HID 设备。
10. 机箱、主板和设备应具备基本物理管理，避免学生轻易拆机清除固件设置。

#### 自动检测能力

DeviceSecurity Module 应尽可能读取：

- Secure Boot 是否开启；
- 固件类型是否为 UEFI；
- TPM 是否存在（只做状态展示，不作为 V7.0 强制依赖）；
- 当前系统盘和启动模式；
- 可识别的启动项；
- 可识别的 USB/外部启动策略；
- 可识别的 PXE/Network Boot 状态；
- BIOS 厂商、型号、版本；
- 最近一次设备安全检查时间；
- 管理员人工核验结果。

#### 人工核验能力

由于不同厂商 BIOS/UEFI 接口差异明显，以下项目允许采用人工确认：

- BIOS 管理员密码是否设置；
- Boot Menu 是否锁定；
- USB Boot 是否完全关闭；
- External Device Boot 是否关闭；
- PXE 是否关闭；
- Boot Order 是否锁定；
- 清 CMOS 后密码是否仍受厂商保护。

人工核验必须记录：

- 设备编号；
- 操作管理员；
- 核验时间；
- 固件版本；
- 各检查项结果；
- 证据备注；
- 下次复检日期。

#### 设备安全评分

| 检查项 | 建议权重 |
|--------|----------|
| 学生使用标准用户账户 | 20 |
| BIOS/UEFI 管理员密码已设置 | 20 |
| USB/外部启动已关闭 | 20 |
| PXE/网络启动已关闭 | 10 |
| Boot Order/Boot Menu 已限制 | 10 |
| Secure Boot 已开启 | 10 |
| Windows USB 存储策略正常 | 10 |

评分等级：

- 90～100：低风险；
- 75～89：可部署但需整改提示；
- 60～74：高风险，不建议交付；
- 60 以下：禁止标记为合格设备。

#### 失败与降级策略

| 情况 | 处理 |
|------|------|
| Secure Boot 关闭 | 高风险告警，不自动假定安全 |
| BIOS 状态无法读取 | 标记“需人工核验”，不得显示为已通过 |
| USB Boot 状态无法读取 | 要求管理员人工确认 |
| 发现 PXE 启动项 | 提示关闭并重新验收 |
| Windows USB 存储策略失效 | 自动恢复并记录 |
| 设备更换主板或更新 BIOS | 安全评分失效，要求重新核验 |
| 启动配置发生变化 | 重新生成设备安全报告 |
| 管理员跳过检查 | 标记“未完成部署安全验收” |

#### 验收标准

- [ ] Secure Boot 状态读取正确。
- [ ] 不支持自动读取的 BIOS 项不会被误报为“已关闭”。
- [ ] 管理员可以完成逐项人工确认并保存记录。
- [ ] USB Boot、PXE、Boot Order、Boot Menu 均进入部署检查清单。
- [ ] 设备固件变化后会要求重新核验。
- [ ] 不使用 BitLocker 的能力边界在产品界面和部署文档中明确显示。
- [ ] Windows 中禁用 USB 存储不影响键盘、鼠标和必要 HID 设备。
- [ ] 设备安全评分可以追溯到每个原始检查项。

## 六、非功能需求

### 6.1 性能

- 空闲 CPU 平均占用低于 1%。
- 常态内存总占用目标低于 200 MB。
- 应用启动判断不明显影响学生操作。
- Agent 登录启动时间不超过 5 秒。
- 20 秒代理校验不得造成网络卡顿。

### 6.2 稳定性

- 连续运行 7 天无崩溃。
- 支持异常断电恢复。
- 支持 Windows 更新后自动恢复服务。
- 更新、维护和策略切换不得造成系统循环重启。

### 6.3 可测试性

每个安全功能必须具备正常路径、异常路径、权限边界、故障注入、恢复、回滚和日志验证。

## 七、V7.0 发布验收标准

1. 威胁模型和部署前提写入安装手册。

10. 文件损坏可自动恢复。
