# V7.0 组件架构设计

> **版本**：V7.0
> **状态**：第1周交付物
> **基线**：.NET 8.0 LTS、net8.0-windows、Windows 10/11 Pro 正式支持
> **编制日期**：2026-08-28
> **配套文档**：《V7.0 威胁模型与安全边界》

---

## 一、文档目的

本文档定义 Winknow V7.0 的组件架构、运行身份、启动流程状态机和组件间通信契约。

本文档是第1周"项目拆分"和"运行身份设计"的交付物，所有组件的实现必须符合本文档定义的职责边界、运行身份和启动流程。

## 三、组件详细设计

### 3.1 ControlService（核心管控服务）

**类型**：Windows Service（`Microsoft.Extensions.Hosting.Worker` + `AddWindowsService()`）

**运行身份**：`NT AUTHORITY\SYSTEM`（LocalSystem）

**服务名**：`Winknow Control Service`

**入口**：`src/Winknow.ControlService/Program.cs`

**启动方式**：系统启动时由 SCM 自动启动（`Automatic`）

**核心职责**：
1. 软件管控
   - WMI `ProcessStartTrace` 实时监听新进程
   - Service 启动时全量进程扫描
   - 1-2 秒周期进程扫描
   - 路径 + 签名 + Hash + 用户 + 父进程 + 命令行综合判断
   > 注：进程名不能作为唯一放行依据
2. 策略执行
   - 加载并验证策略文件（签名 + 版本 + Hash）
   - 软件白名单 / 网站白名单 / USB 管控策略
3. IPC 服务端
   - 监听 Named Pipe（`\\.\pipe\Winknow_Control`）
   - 校验调用方 SID
   - 防重放（时间戳 + 随机数 + 设备 ID）
4. 自保护
   - 配置服务 DACL（仅 SYSTEM 和管理员可停止）
   - 配置程序目录文件 ACL
   - 配置关键注册表 ACL
5. 日志审计
   - 所有管控决策写入 `audit.db`（Hash Chain）
   - 关键事件写入 Windows Event Log

**禁止**：
- ControlService **不承担**交互式键盘钩子（由 SessionAgent 负责）
- ControlService **不直接**显示 UI（通过 AdminUI 管理）
- ControlService **不持有**学生用户令牌

**依赖**：
- `Winknow.Core`、`Winknow.Ipc`、`Winknow.Policy`、`Winknow.ProcessControl`
- `Winknow.Network`、`Winknow.Security`、`Winknow.Logging`、`Winknow.DeviceSecurity`

### 3.2 GuardService（守护服务）

**类型**：Windows Service（`Microsoft.Extensions.Hosting.Worker` + `AddWindowsService()`）

**运行身份**：`NT AUTHORITY\SYSTEM`（LocalSystem）

**服务名**：`Winknow Guard Service`

**入口**：`src/Winknow.GuardService/Program.cs`

**启动方式**：系统启动时由 SCM 自动启动（`Automatic`）

**核心职责**：
1. 守护 ControlService
   - 每 1-2 秒查询 ControlService 状态（`QueryServiceStatus`）
   - 若 ControlService 被停止，立即调用 `StartService` 重启
   - 若 ControlService 进程被终止，立即重启服务
2. 自保护
   - GuardService 与 ControlService 互相守护
   - 服务 DACL 加固（仅 SYSTEM 和管理员可停止）
3. 审计
   - 守护事件写入 Windows Event Log
   - 检测到的异常停止记录到 `audit.db`

**禁止**：
- GuardService **不承担**软件管控、网络管控、USB 管控等业务逻辑
- GuardService **不直接**与 SessionAgent 通信

**依赖**：
- `Winknow.Core`、`Winknow.Ipc`

### 3.3 SessionAgent（会话代理）

**类型**：用户态进程（`WinExe`，无控制台窗口）

**运行身份**：学生用户（当前登录的标准用户）

**入口**：`src/Winknow.SessionAgent/Program.cs`

**启动方式**：由 ControlService 在用户登录时启动（`CreateProcessAsUser`）

**实例数**：每个活动用户会话 1 个（通过会话枚举 + 互斥锁保证）

**核心职责**：
1. 会话内交互
   - 键盘钩子（`SetWindowsHookEx` + `WH_KEYBOARD_LL`）
   - 屏幕控制（如需要）
   - 课堂模式时间控制
2. IPC 客户端
   - 连接到 ControlService 的 Named Pipe
   - 接收策略更新通知
   - 上报会话状态
3. 自清理
   - 用户注销时自动退出
   - 防止残留进程

**禁止**：
- SessionAgent **不执行**软件终止决策（决策权在 ControlService）
- SessionAgent **不持有**管理员权限
- SessionAgent **不直接**修改注册表或文件 ACL

**依赖**：
- `Winknow.Core`、`Winknow.Ipc`

### 3.4 AdminUI（管理界面）

**类型**：WPF 应用（`WinExe`）

**运行身份**：管理员（需 UAC 提权）

**入口**：`src/Winknow.AdminUI/Program.cs`（实际由 `App.xaml` 启动）

**启动方式**：管理员手动启动（UAC 提示）

**核心职责**：
1. 策略管理
   - 编辑软件白名单 / 网站白名单 / USB 策略
   - 签名策略文件并下发到 ControlService
2. 设备安全
   - 显示 DeviceSecurity 评分
   - 核验报告展示
   - 风险项提示（如 Secure Boot OFF）
3. 日志查看
   - 查询 `audit.db`
   - 完整性状态显示
   - CSV 导出
4. 维护模式
   - 密码验证、TOTP
   - 维护状态展示

**禁止**：
- AdminUI **不常驻**运行（管理员操作完即退出）
- AdminUI **不直接**修改系统配置（通过 IPC 下发命令给 ControlService）

**依赖**：
- `Winknow.Core`、`Winknow.Ipc`、`Winknow.Policy`、`Winknow.DeviceSecurity`、`Winknow.Logging`

### 3.5 TrustedUpdater（可信更新器）

**类型**：控制台应用（`Exe`）

**运行身份**：`NT AUTHORITY\SYSTEM`（由 ControlService 或计划任务拉起）

**入口**：`src/Winknow.TrustedUpdater/Program.cs`

**核心职责**：
1. 签名验证
   - 验证更新包签名（公钥验证，私钥不在此处）
   - 验证版本号、Hash
2. A/B 部署
   - 双分区切换
   - 旧版本保留（用于回滚）
3. 自动回滚
   - 更新后健康检查失败 → 自动回退到旧版本
4. 策略签名
   - 策略文件签名验证（Policy Signature）

**禁止**：
- TrustedUpdater **不持有**正式签名私钥
- TrustedUpdater **不自动**联网下载（由管理员手动提供更新包）

**依赖**：
- `Winknow.Core`、`Winknow.Security`

### 3.6 RecoveryTool（恢复工具）

**类型**：控制台应用（`Exe`）

**运行身份**：管理员（或在 PE 环境下运行）

**入口**：`src/Winknow.RecoveryTool/Program.cs`

**核心职责**：
1. 离线授权
   - 维护模式密码验证
   - TOTP 二次验证
2. 维护模式
   - 临时停止 ControlService 和 GuardService
   - 设置维护期倒计时
   - 维护期结束自动恢复
3. 紧急恢复
   - 策略文件损坏时恢复默认策略
   - 服务配置损坏时重置
   - 审计日志损坏时从 Hash Chain 恢复

**禁止**：
- RecoveryTool **不能**在学生用户下运行
- RecoveryTool **不持有**管理员密码明文

**依赖**：
- `Winknow.Core`

## 四、运行身份设计

### 4.1 身份总表

| 组件 | 运行身份 | 启动者 | 是否需要 UI | 是否需要网络 |
|------|---------|--------|------------|------------|
| ControlService | LocalSystem | SCM | 否 | 是（网站白名单检测） |
| GuardService | LocalSystem | SCM | 否 | 否 |
| SessionAgent | 学生用户 | ControlService | 是（隐藏窗口） | 否 |
| AdminUI | 管理员（UAC） | 管理员手动 | 是 | 否 |
| TrustedUpdater | LocalSystem | ControlService | 否 | 否 |
| RecoveryTool | 管理员/PE | 管理员手动 | 否 | 否 |

### 4.2 LocalSystem 身份说明

**使用 LocalSystem 的组件**：ControlService、GuardService、TrustedUpdater

**理由**：
- 需要枚举所有会话的进程（包括其他用户会话）
- 需要终止其他用户进程
- 需要修改系统级注册表和文件 ACL
- 需要以任意用户身份启动 SessionAgent（`CreateProcessAsUser`）
- 需要查询 WMI 事件（`ProcessStartTrace`）

**限制**：
- LocalSystem 服务**不显示** UI（Session 0 隔离）
- LocalSystem 服务**不直接**访问网络共享（使用服务账户）

### 4.3 学生用户身份说明

**使用学生用户的组件**：SessionAgent

**理由**：
- SessionAgent 必须在用户会话内运行才能设置键盘钩子
- SessionAgent 不需要管理员权限（决策权在 ControlService）
- 学生用户身份限制了 SessionAgent 的能力，防止被滥用

**限制**：
- 学生用户**不能**停止服务（DACL 限制）
- 学生用户**不能**修改程序目录（ACL 限制）
- 学生用户**不能**修改关键注册表（ACL 限制）

### 4.4 管理员身份说明

**使用管理员的组件**：AdminUI、RecoveryTool

**理由**：
- 需要修改系统配置（策略、服务、ACL）
- 需要执行维护操作（维护模式、恢复）

**限制**：
- 管理员操作必须通过 UAC 提权
- 管理员操作全程审计
- 管理员密码**不长期保存**在内存

### 4.5 敏感数据处理规范

**遵循 V7.0 安全编码规范**：

- 禁止长期保存密码 string
- 密码和密钥明文生命周期必须尽可能短
- byte[] / char[] 敏感缓冲区使用后立即清理
  - 对 byte[] 优先使用 `CryptographicOperations.ZeroMemory()`
- 持久化密钥使用 DPAPI / HSM / 安全凭据存储
- **不得依赖 SecureString 作为新的安全架构核心**

## 五、启动流程状态机

### 5.1 系统启动流程

```
系统开机
  ↓
SCM 启动 ControlService（Automatic）
  ↓
ControlService 启动流程：
  ├─ 加载配置
  ├─ 初始化日志（audit.db + Event Log）
  ├─ 验证策略文件签名
  ├─ 启动 WMI ProcessStartTrace 监听
  ├─ 执行全量进程扫描
  ├─ 启动周期扫描定时器（1-2 秒）
  ├─ 启动 Named Pipe 服务端
  └─ 启动 SessionAgent 监听器
  ↓
SCM 启动 GuardService（Automatic）
  ↓
GuardService 启动流程：
  ├─ 加载配置
  ├─ 初始化日志
  └─ 启动 ControlService 状态监控循环
  ↓
ControlService 监听到用户登录事件
  ↓
ControlService 调用 CreateProcessAsUser 启动 SessionAgent
  ↓
SessionAgent 启动流程：
  ├─ 创建互斥锁（防止多实例）
  ├─ 设置键盘钩子（WH_KEYBOARD_LL）
  ├─ 连接 ControlService Named Pipe
  └─ 进入消息循环
```

### 5.2 用户登录流程

```
用户登录（Logon）
  ↓
ControlService 接收 SESSION_CHANGE_NOTIFICATION
  ├─ WTS_SESSION_LOGON
  ├─ 获取会话 ID
  ├─ 获取用户 SID
  └─ 校验是否为学生用户
  ↓
是学生用户？
  ├─ 是 → CreateProcessAsUser 启动 SessionAgent
  └─ 否 → 忽略（管理员登录不启动 SessionAgent）
  ↓
SessionAgent 启动并连接 IPC
  ↓
ControlService 下发当前策略给 SessionAgent
```

### 5.3 用户注销流程

```
用户注销（Logoff）
  ↓
ControlService 接收 SESSION_CHANGE_NOTIFICATION
  ├─ WTS_SESSION_LOGOFF
  └─ 获取会话 ID
  ↓
ControlService 向对应 SessionAgent 发送退出信号
  ↓
SessionAgent 收到信号：
  ├─ 卸载键盘钩子
  ├─ 关闭 IPC 连接
  ├─ 释放互斥锁
  └─ 进程退出
  ↓
ControlService 检测到 SessionAgent 退出，清理会话状态
```

### 5.4 服务停止流程

```
服务停止请求（管理员通过 RecoveryTool）
  ↓
ControlService 进入维护模式
  ├─ 暂停 WMI 监听
  ├─ 暂停周期扫描
  ├─ 通知所有 SessionAgent 进入只读模式
  └─ 等待进行中的操作完成
  ↓
ControlService 停止
  ↓
GuardService 检测到 ControlService 停止
  ↓
GuardService 检查维护模式标志
  ├─ 维护模式 ON → 不重启，记录审计
  └─ 维护模式 OFF → 立即重启 ControlService
```

### 5.5 更新流程

```
管理员提供更新包
  ↓
TrustedUpdater 启动（由 ControlService 拉起）
  ↓
TrustedUpdater 验证更新包签名
  ├─ 签名有效 → 继续
  └─ 签名无效 → 拒绝，记录审计
  ↓
TrustedUpdater 执行 A/B 部署
  ├─ 备份当前版本到 A 分区
  ├─ 安装新版本到 B 分区
  └─ 切换启动分区到 B
  ↓
系统重启
  ↓
新版本 ControlService 启动
  ↓
健康检查（启动后 30 秒内）
  ├─ 健康 → 更新成功，标记 B 分区为稳定
  └─ 异常 → 自动回滚到 A 分区，重启
  ↓
回滚后审计记录更新失败原因
```

### 5.6 异常恢复流程

```
ControlService 异常终止（非正常停止）
  ↓
GuardService 检测到状态变化
  ↓
GuardService 立即调用 StartService 重启 ControlService
  ↓
ControlService 重启后：
  ├─ 加载上次策略
  ├─ 重新启动 WMI 监听
  ├─ 重新启动全量扫描
  ├─ 重新连接所有 SessionAgent
  └─ 记录异常终止事件到审计日志
```

## 六、组件间通信契约

### 6.1 IPC 通信概述

| 通信路径 | 方式 | 身份校验 | 防重放 |
|---------|------|---------|--------|
| ControlService ↔ SessionAgent | Named Pipe | SID 校验 | 时间戳 + 随机数 + 设备 ID |
| ControlService ↔ GuardService | 直接 API + SCM | LocalSystem 互信 | - |
| AdminUI → ControlService | Named Pipe | 管理员 SID | 时间戳 + 随机数 |
| TrustedUpdater ← ControlService | 进程拉起 | LocalSystem 互信 | - |

### 6.2 Named Pipe 安全配置

```
Pipe 路径：\\.\pipe\Winknow_Control
Pipe ACL：
  - SYSTEM：完全控制
  - Administrators：完全控制
  - 当前会话用户：读写
  - 其他：拒绝
```

### 6.3 消息协议

```
消息结构：
  ├─ Version（协议版本，uint16）
  ├─ RequestId（请求号，uint32，单调递增）
  ├─ Timestamp（时间戳，Unix 毫秒）
  ├─ Nonce（随机数，16 字节）
  ├─ DeviceId（设备 ID，16 位 hex）
  ├─ SenderSid（发送方 SID）
  ├─ MessageType（消息类型，uint16）
  ├─ PayloadLength（载荷长度，uint32）
  └─ Payload（载荷，JSON 或二进制）

防重放规则：
  - 时间戳偏差超过 ±60 秒 → 拒绝
  - RequestId 必须大于上次收到的值
  - Nonce 在 5 分钟内不得重复
  - DeviceId 必须与本机匹配
```

## 七、项目拆分验证

```

│  ├─ Winknow.ProcessControl/    # 进程管控
│  ├─ Winknow.Network/           # 网络管控
│  ├─ Winknow.Security/          # 加密与签名
│  ├─ Winknow.Logging/           # 审计日志
│  ├─ Winknow.DeviceSecurity/    # 设备安全
│  ├─ Winknow.ControlService/    # 核心服务
│  ├─ Winknow.GuardService/      # 守护服务
│  ├─ Winknow.SessionAgent/      # 会话代理
│  ├─ Winknow.AdminUI/           # 管理界面
```
