# 灰度部署方案与报告模板（V7.0 第 13 周）

> 依据：《编程课堂电脑管控系统 V7.0 基础版开发计划书》第 13 周"灰度部署"与 M8 里程碑。
> 适用版本：V7.0 候选版（RC），构建产物由 `installer/Build-Release.ps1` + `installer/Sign-Release.ps1` 产出。

---

## 一、灰度总原则

1. **先候选后正式**：灰度只部署"已签名 RC 安装包"，不部署开发机直接编译的产物。
2. **可回滚**：任何一台灰度机必须具备两条回退路径——V7.0 内部回滚（`TrustedUpdater rollback`，回退到 Previous 槽）和整包回退（卸载 V7.0，重装 V6.0 稳定版）。
3. **不锁死**：灰度机必须预先验证《维护模式操作手册》的紧急退出流程（维护模式授权 + 卸载），确保不存在"永久锁死电脑"路径。
4. **逐步放量**：三阶段之间设置"发布门槛复评"，任何一项 P0/P1 缺陷未关闭则暂停放量。
5. **数据留痕**：每台灰度机每天填写一份《灰度日报》（见第四节模板），阶段结束汇总为《灰度阶段报告》。

## 三、灰度阶段与放量条件

### 第一阶段：2 台测试机 × 2 天

- 设备：管理员自用测试机（1 台笔记本 + 1 台台式机，最好覆盖 2 个品牌）。
- 操作：全功能演练——安装、策略下发、未授权软件拦截、USB 阻止、DeviceSecurity 检测、更新与回滚演练各 1 次。
- 通过条件（全部满足才进入第二阶段）：
  - 无 P0 缺陷；
  - 双服务 48 小时无崩溃重启；
  - `TrustedUpdater rollback` 演练成功；
  - 手动断电/强杀服务各 1 次，系统可自愈（Guard 拉起 + 重启限流未触发降级误判）。

### 第二阶段：5 台学生机 × 2 天

- 设备：真实学生机，覆盖 ≥ 3 个品牌/主板系列（对照《多品牌 BIOS 兼容矩阵》选择 Dell / Lenovo / HP / 华硕 + 其他）。
- 操作：正常上课使用（编程课 + 洛谷练习），管理员仅远程观察，不做现场干预。
- 通过条件（全部满足才进入第三阶段）：
  - 无 P0 缺陷，P1 缺陷有结论或修复计划；
  - 关键编程软件（Dev-C++、VS Code、Code::Blocks、洛谷浏览器访问）零阻断性误拦；
  - 键鼠（HID）不受 USB 策略影响；
  - 学生端无感知投诉（误拦、卡顿）≤ 1 起/天且可解释。

### 第三阶段：10～20 台学生机 × ≥ 3 天

- 设备：一个完整机房或两个半机房，含 1 台最老机型与 1 台最新机型。
- 操作：连续真实上课 ≥ 3 天，其中至少 1 天跨越周末冷启动、至少 1 次课堂断电演练（下课断闸）。
- 通过条件（对应《发布决策检查单》12 项发布门槛全部勾选）：
  - 12 项观察指标（见第四节）全部达标或可接受；
  - 7 天连续运行测试完成或已在第一阶段等效覆盖（含跨 Windows 更新）；
  - 正式发布评审通过并签字。

### 放量/熔断规则

- **熔断**：任一灰度机出现 P0（锁死、蓝屏、双进程重启风暴、系统级网络中断），立即执行：停止放量 → 该机 `rollback` 或整包回退 V6.0 → 采集日志（哈希链校验导出）→ 复评。
- **回退优先**：疑似策略问题先切"安全降级模式"（SafeDegradedMode，第 10 周），疑似更新问题用 Previous 槽回滚，均无效才整包回退。

## 七、回退到 V6.0 的标准流程（发布门槛 #12）

1. 该机进入维护模式（维护授权码），停止管控；
2. 控制面板/安装包卸载 Winknow V7.0（卸载向导会提示"数据保留/清除"，选择保留时 `C:\ProgramData\Winknow` 下的日志与策略不清除）；
3. 确认双服务已删除（`sc query WinknowControl` / `sc query WinknowGuard` 均报 1060）；
4. 安装 V6.0 稳定版安装包，恢复 V6.0 策略（使用升级前备份）；
5. 验证 V6.0 服务 Running、拦截功能正常，填写《部署核验记录》。

> 注：V7.0 → V6.0 属跨大版本回退，不走 Previous 槽（Previous 只保存 V7.0 上一小版本）；必须整包回退。
