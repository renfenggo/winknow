# BitLocker 剩余风险说明（V7.0 不采用全盘加密）

> V7.0 第 12 周交付 | 对应计划书验收："风险说明——不采用 BitLocker 的剩余风险"
> 结论先行：V7.0 **不使用、不检测、不依赖** BitLocker/TPM；本文档量化该决策的剩余风险与 V7.0 的补偿性缓解

---

## 1. 边界声明

| 维度 | V7.0 的态度 |
|------|-------------|
| 使用 | 不启用、不管理 BitLocker（部署脚本不含 enable-bitlocker） |
| 检测 | 设备安全模块不做 BitLocker/TPM 状态检测与评分（检查项模型中无此项） |
| 依赖 | 不依赖 TPM 存放任何密钥（密钥体系见第 9 周密钥清单：DPAPI/HSM） |
| 共存 | 学校镜像若统一启用 BitLocker，与 Winknow 正交运行，互不干预 |

## 2. 不采用的理由

1. **威胁模型错位**：BitLocker 防的是"物理盗取硬盘后的离线数据窃取"（保密性）；编程课堂的核心诉求是**行为管控与考试公平性**（U 盘摆渡、外部启动、代考工具），BitLocker 对此无贡献；
2. **运维成本**：机房数十至上百台机器的 BitLocker 恢复密钥托管（AD/MBAM）超出学校 IT 承载能力；一次主板维修（换 TPM）即触发恢复模式，机房停摆风险高；
3. **故障面**：BitLocker 与系统重装镜像流程（机房常态）冲突——每次重装需解密/重新加密，批量部署时间成本高；
4. **V7.0 防线已覆盖核心威胁**：启动防线（Secure Boot + USB/PXE 禁用）+ 进程管控 + 审计哈希链。

## 3. 剩余风险量化

| # | 场景 | 攻击成本 | 数据/后果 | V7.0 缓解 | 残余风险 |
|---|------|----------|-----------|-----------|----------|
| R1 | 拆下硬盘接到另一台机器离线读取学生作业/缓存 | 需物理开机箱 + 螺丝刀（A3 物理层） | 学生代码泄露（隐私）；**不含** Winknow 密钥（DPAPI Machine Scope 绑定原机，换机不可解密） | 审计库/密钥加密使其读到的仅是密文与明文策略 | 低（机房财产受控，硬盘拆卸有管理痕迹） |
| R2 | 离线篡改系统盘后装回（植入启动项/恶意驱动） | 同上 + 离线挂载改写 | 绕过进程管控的可能 | Secure Boot（UEFI 签名链）使未签名引导项失效；核心文件哈希校验（第 7/10 周）检测篡改 | 中低（签名链覆盖内核态；用户态篡改由哈希链发现） |
| R3 | Live USB 进 PE 清除 Winknow（SAM/服务注册表离线删除） | U 盘 + 重启（若 BIOS 加固失效） | 管控失效 | **BIOS 七项加固是主防线**（USB Boot/Boot Menu/密码禁用外部引导）；第 11/12 周核验闭环确保加固在位 | 中（依赖 BIOS 加固持续有效——复检机制覆盖） |
| R4 | 盗取整机后读取数据 | 搬走整台机器 | 同 R1 | 机房物理管理 | 低（超出软件系统边界，属物业管理） |

## 4. 残余风险接受理由

- R1/R4 的**物理窃取**威胁在教室场景中由物理资产管理（机箱锁、机房门禁）覆盖成本更低；
- R2/R3 的**离线攻击**前提是先突破 BIOS 加固——复检机制（部署清单 C 段：BIOS 更新/主板更换触发强制复检）+ 变化失效机制（固件指纹变化自动作废核验）构成闭环；
- 若学校未来上线域环境与 MBAM，可叠加 BitLocker 而无需改动 Winknow（正交部署）。

## 5. 升级路径（超出 V7.0 范围）

- V7.1 评估项：TPM 在位检测（只检测不依赖）、BitLocker 状态展示（只读、不计分）；
- 保持原则：任何加密状态的展示**不参与设备安全评分**（防止"有 BitLocker 就忽视 BIOS 加固"的错误安全观——启动防线不可被替代）。
