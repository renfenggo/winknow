# 编程课堂电脑管控系统 V7.0 —— 第 9 周交付文档：密钥、日志完整性与隐私治理

> **里程碑**：M9 数据安全完成
> **周期**：第 9 周（密钥清单、日志加密、哈希链、检查点、事件锚点、数据保留、隐私声明）
> **基线**：V7.0 网络防绕过版（第 8 周交付）
> **目标**：建立统一密钥体系和可验证日志——每台设备独立生成日志密钥（DPAPI 保护），敏感正文 AES-GCM 加密，哈希链 + 签名检查点保证日志不可篡改不可截断，关键事件双写 Windows 事件日志，30 天保留期到期安全删除
> **验收标准**：客户端不包含签名私钥；密码、密钥、恢复码不进入普通日志；修改或截断日志可被检测；默认不记录网页正文和学生代码正文

## 三、架构与流程设计

### 3.1 密钥治理体系

```
┌──────────────────────────────────────────────────────────────┐
│                    KeyManifest（密钥清单）                      │
│  CodeSigning │ LogEncryption │ LogCheckpoint │ Totp │ Recovery│
│  外部HSM      │ 设备生成      │ 设备生成       │ 管理员│ 管理员  │
│  仅公钥❗     │ AES-256-GCM  │ HMAC-SHA256   │ 配置  │ 配置    │
└──────┬───────┴──────┬───────┴───────┬──────┴──┬────┴────┬────┘
       │              │               │         │         │
       │         ┌────▼───────────────▼────┐    │         │
       │         │  DeviceLogKeyGenerator   │    │         │
       │         │  首次: RandomNumber 32B  │    │         │
       │         │  持久: DPAPI Machine     │    │         │
       │         │        Scope + 设备ID熵  │    │         │
       │         └────┬───────────────┬────┘    │         │
       │              │               │         │         │
       │         ┌────▼────┐    ┌─────▼─────┐ ┌─▼─────┐ ┌─▼──────┐
       │         │LogCipher│    │LogCheckp- │ │TotpGen│ │Recovery│
       │         │AES-GCM  │    │ointSigner │ │SHA1   │ │CodeHash│
       │         │正文加密  │    │链尾签名    │ │       │ │SHA-256 │
       │         └─────────┘    └───────────┘ └───────┘ └────────┘
       │
  客户端仅持公钥验签（私钥在受控构建环境 HSM/Token）
```

**密钥分离原则**：日志加密密钥（机密性）与检查点签名密钥（完整性）相互独立，泄露其一不影响另一属性；签名私钥永不落客户端。

### 3.2 日志写入与验证流水线

```
日志事件产生
     │
     ▼
┌─────────────┐   敏感字段？ ┌─────────────┐
│ PrivacyPolicy │───是──────▶│  LogCipher   │
│ FilterFields │            │  AES-GCM 加密│
│ （排除字段）  │            └──────┬──────┘
└──────┬──────┘                   │
       │ 允许的字段                 │ Base64 密文
       ▼                          ▼
┌─────────────────────────────────────┐
│  HashChain.ComputeChainHash(record)  │
│  Hash = SHA256(prevHash ‖ record)    │
└──────────────────┬──────────────────┘
                   │ 每条记录
                   ▼
┌─────────────────────────────────────┐
│  LogCheckpointSigner（每 100 条）     │
│  Checkpoint = HMAC(tailHash,count,ts)│
└──────────────────┬──────────────────┘
                   │ 关键事件
                   ▼
┌─────────────────────────────────────┐
│  EventLogAnchor（双写 Windows 日志）  │
│  9001 安全 / 9002 维护 / 9003 更新   │
└─────────────────────────────────────┘
```

### 3.3 篡改/截断检测原理

| 攻击方式 | 检测机制 |
|----------|----------|
| 修改中间记录内容 | 该记录 Hash 与存储值不匹配 → `VerifyChain` 返回断裂点索引 + `HashMismatch` |
| 删除中间记录 | 后一条的 `PreviousHash` 与前一条的 `Hash` 断链 → `VerifyChain` 失败 |
| 整段删除后拼接首尾 | 链尾 Hash 与最近检查点签名不匹配 → `VerifyContinuity` 返回 `SignatureInvalid` |
| 伪造检查点 | 无 HMAC 密钥无法生成合法签名 → `VerifyCheckpoint` 常量时间比较失败 |
| 删除整个审计数据库 | 检查点之前的关键事件仍存于 Windows Event Log（`EventLogAnchor` 双写） |
| 修改密文正文 | AES-GCM tag 校验失败 → `Decrypt` 返回 `DecryptionFailed` |

### 3.4 数据生命周期

```
写入 → 哈希链 → 检查点签名 → 事件锚点双写
                                    │
                    ┌───────────────▼───────────────┐
                    │  DataRetentionManager          │
                    │  默认 30 天（可配置）            │
                    │  启动时 + 周期 PurgeExpired     │
                    │  DELETE + VACUUM（覆盖空闲页）  │
                    └───────────────┬───────────────┘
                                    │ 单文件销毁
                                    ▼
                    SecureDeleteFile：随机覆盖 → Flush(true) → Delete
```

### 6.1 本次实现细节

1. **密钥清单先行**：以 `KeyManifest` 作为密钥治理的单一声明源，5 类密钥的用途/来源/存储/算法全部结构化声明，"客户端不含签名私钥"从口头约定变为机器可验证的清单断言。

2. **DPAPI + 设备 ID 熵值双层保护**：密钥文件除 DPAPI Machine Scope 外，附加设备 ID 作为 `optionalEntropy`——即使密钥文件被复制到同域其他机器，无熵值仍无法解密（`DpapiProtector_Unprotect_WrongEntropy_ThrowsCryptographicException` 验证）。

3. **加密密钥与签名密钥分离**：`log_enc.key`（AES-256）与 `log_hmac.key`（HMAC-SHA256）独立生成、独立存储，避免单密钥泄露同时破坏机密性与完整性。

4. **AES-GCM 存储格式**：`Base64(nonce[12] ‖ ciphertext ‖ tag[16])`，每次加密随机 nonce 保证同明文密文不同（语义安全），tag 校验同时提供密文完整性。

5. **检查点密钥签名的对象是"链尾 Hash + 记录数 + 时间戳"**：篡改任一字段均导致签名失效；验证使用 `CryptographicOperations.FixedTimeEquals` 常量时间比较防时序旁路。

6. **EventLogAnchor 降级设计**：事件源注册需管理员，失败时仅记录警告不阻断服务主流程（课堂环境 ControlService 以 LocalSystem 运行，正常路径下可注册成功）。

7. **VACUUM 作为安全删除手段**：SQLite `DELETE` 不物理清除页数据，`VACUUM` 重建数据库文件使已删除记录不可恢复，符合"到期安全删除"要求；单文件销毁另有 `SecureDeleteFile` 随机覆盖。

8. **Worker 集成的失败容忍**：密钥初始化失败（如 DPAPI 不可用）仅记录错误并跳过日志基础设施初始化，不阻断管控主流程——进程管控/网络管控的可用性优先于日志加密。

### 7.2 硬约束遵循

- ✅ TargetFramework = `net8.0-windows`（.NET 8 LTS；DPAPI/EventLog 仅 Windows）
- ✅ 复用 `ErrorCode` 既有值（`EncryptionFailed`/`DecryptionFailed`/`HashMismatch`/`SignatureInvalid`/`PathNotFound`），未私造错误码
- ✅ 不使用 SecureString（密码字节 `CryptographicOperations.ZeroMemory` 清零，与项目约定一致）
- ✅ 常量时间比较（`FixedTimeEquals`）用于所有哈希/签名校验，防旁路
- ✅ `TrustedUpdater`（第 7 周）签名验签链路不受影响——本周五类密钥与更新签名体系正交
